AT 与 AT+CC 在 QuantumKatas 上的复现

论文：Gibbs, Tibshirani, Han, Zrnic, Reliable AI-Assisted Decisions via Selective Auditing（arXiv:2610.31662v1）。在已有缓存数据上追加的实验，不是预注册主实验。没有新增 API 调用。

结论

  • 漏审错误比例控制住了。主题序下，三个 generator、四个 α_leak 的漏审错误比例（多次审计随机性的计数期望之比）都在目标附近，例如 α_leak = 10% 时为 9.9% 到 11.0%。但单次运行的波动很大，Sonnet 只有 35 道错题，单次运行的 5%–95% 区间可以从 0% 到 20% 以上。
  • 省下的审计很少。审计率只比随机审计（每题以 1 − α 的概率审）低几个百分点，比如 α_leak = 10% 时为 81% 到 87%，随机审计为 90%；而事后最优阈值只要 56% 到 76%。原因是数据流短：为了让理论误差项变小，开发数据选出的 γ = 0.5，即高置信度题也要抽查一半。
  • 在线校准改善了 Brier，但没有明显减少审计。AT+CC 的 Brier 比原始置信度低（Qwen3 0.32 → 0.23，gpt-oss 0.26 → 0.19），但和 AT 的配对审计率差都在 ±5 个百分点内，区间都包含 0。
  • 自动接受集合里的错误率很高。因为论文约束的是「漏掉的错误占全部错误的比例」，Qwen3 和 gpt-oss 自动接受的答案里有 21% 到 38% 是错的；这和我们约束的「放行答案的错误率」是两个不同的指标。
  • 和我们的方法只能作跨协议参照。AT 每次审计都会纠正错误、只靠在线审计拿标签；我们的方法不纠正、用约 258 道带标签训练题和付费 verifier。下面的对照表逐项列出了差异。

设置

  • 语义：H = 0 自动接受原始候选，不读取标签；H = 1 转交审计，读取官方 checker 标签。候选和原始标签都不改；不声称生成了修正答案。学习器只能通过受控 oracle 在审计时拿到标签。
  • 数据：Qwen3、gpt-oss、Sonnet 5.5 的固定候选和原始 p_correct。可评估题数 310 / 308 / 322，排除 12 / 14 / 0 道无代码、无置信度的失败题（另做含失败题的敏感性分析）。
  • 超参数（论文没有给出具体数值，这里是我们的选择）：在 GPQA 的 249 道 calibration 题上选定后冻结，η = 1，γ = 0.5，AT+CC 的 β = 1，网格 21 个点（步长 0.05），τ₁ = 0.5，w₁ 均匀。第一轮搜索（η ≤ 0.2，γ ≤ 0.2）没有可行解，所以在开发数据上扩大过一次搜索范围。
  • 随机性：每种题序 100 个审计随机种子，所有方法共用同一组随机数，但各自按自己的审计概率决定是否审计。题序：主题序、按 kata 分组的原始顺序，以及另外 20 种随机题序。种子和题序不是新增的独立题目。
  • 成本：每次 H = 1 算一次逻辑审计，主成本指标是审计次数和审计比例；置信度来自原生成调用，不重复计费；新增 API 支出为 0；本地更新每次运行最多 0.18 毫秒。没有给审计定美元单价。

主结果（主题序，100 次审计随机性）

「漏审错误比例」是计数期望之比 E[M] / E[E]，即论文的 Err(T)；「单次运行 5%–95%」是每次运行比例的分布。selective risk = M / A，即自动接受答案里的错误率。必审 / 抽查是两类审计的平均次数。Brier 由评估器在全部题目上计算：AT 用原始置信度，AT+CC 用本轮更新前的校准分数。事后最优阈值使用全部标签，不可部署，只作参照。理论误差项 (1/η + 1/γ) / E：Qwen3 2.2%，gpt-oss 2.7%，Sonnet 8.6%，这是期望指标的界，不保证单次运行。

  • 标签权限不同：AT 只在审计时在线拿到标签；我们在每折约 258 道训练题上用全部标签拟合似然和选规则。
  • 动作语义不同：AT 审计后由 auditor 纠正错误，错误不会发布；我们的「不放行」是弃权，不纠正。
  • 信号不同：AT 只用 generator 的置信度；我们还付费调用 verifier。
  • 时机不同：AT 在发布前审计；我们原方案的学习审计发生在发布或弃权决定固定之后。

如果要做同协议比较，需要先定义 oracle-assisted 版本：两者用同一个审计 oracle，同样只在审计时拿标签，「审计」统一为纠正后发布。这需要改动我们方法的反馈设定，所以这里只给出建议，没有执行。

和论文原算法的差异

  • 超参数是我们在开发数据上选的；论文没有给出数值。
  • 数据流只有 308 到 322 轮，远短于论文实验；错题少时理论界很宽。
  • 置信度是 generator 自报的 p_correct，取值很粗（每个 generator 18 到 25 种不同值）。
  • auditor 是缓存的官方 checker 标签，没有生成修正答案。
  • α_leak 取 5%、10%、20%、30%（论文图里是 10% 到 30%）。
