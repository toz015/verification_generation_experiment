Qiskit QuantumKatas · 322 题 · 3 个 generator · 5 折分组交叉拟合

QuantumKatas 验证实验结果

generator 写出完整程序并给出 r（自报通过概率），程序冻结后由 verifier 逐个打分， 顺序策略决定继续问、接受还是弃答。标签是固定版本官方 checker 的 passed。正文全部使用 raw r 作先验， 所有数字都是 322 题的样本外结果。

结论

  • 成立
    verifier 比 generator 自己的信心更会挑出错误程序。 在接受同样多题目的前提下，顺序验证挑出的错题明显少于按 r 从高到低挑： Qwen 31 对 50.5，gpt-oss 22 对 33.7（两者效用差的区间都不含 0）。 Sonnet 的候选 89% 都能通过，verifier 在它上面没有可测的优势。
  • 成立
    顺序验证能提前停止，省下大部分调用。 每题平均调用：Qwen 1.50、gpt-oss 0.94、Sonnet 0.83， 固定问 3 个都是约 2.9–3.0 次，固定问 5 个约 4.8–5.0 次；接受数与效用和固定问 3 个基本相同或略好。
  • 成立
    和只用 r 相比，verifier 显著减少了错误接受。 阈值 0.95 时，Qwen 的错误接受从 81 降到 31， gpt-oss 从 26 降到 22（同时多接受了 18 题）； Sonnet 的接受数从 35 增加到 78，错误率保持约 3%。
  • 未达到
    raw r 下，接受集合的错误率达不到 5% 目标。 r 并不是可信的概率：Qwen 有 81.0% 的 r ≥ 0.95 但只通过 56.8%， gpt-oss 为 53.6% 对 63.3%；Sonnet 则相反，10.9% 对 89.1%。 Qwen 和 gpt-oss 经验证后错误率仍有 16.1% 和 12.0%。附录 A 给出把 r 校准后的结果。

实验设置

数据集

Qiskit QuantumKatas（固定 commit 3790fb3e）把 Microsoft Quantum Katas 的练习改写成 Qiskit/Python 题目，共 350 题， 分布在 26 个主题（kata，如 BasicGates、Teleportation、GroversAlgorithm）以及入门 tutorials 和 examples 中。 每题给出一段带函数签名的题面，要求实现量子电路或经典辅助函数；数据集自带参考解和隐藏测试， 官方 evaluate_solution 在 30 秒内执行测试并返回 passed，我们把它直接作为标签，不修改测试、容差或随机性。 其中 28 题只用于工程调试和 prompt 设计，其余 322 题用于报告的结果。

Prompt

generator 看到原题面和一段固定的执行约定，一次返回完整 Python 模块和 p_correct。verifier 看到同样的题面、执行约定和冻结的代码， 只返回 p_correct；它看不到 generator 的 r、模型名、参考解、测试或其他 verifier 的结果。回复必须恰好是一个 JSON 对象， 否则记为格式失败并计入分母，不修复、不重新生成。

Generator prompt
[system] You write complete Python modules that solve Qiskit QuantumKatas tasks and report a calibrated probability that they pass the official checker. Reply with one JSON object only, never with prose.

Solve the following task from the Qiskit QuantumKatas benchmark.
Task (verbatim from the benchmark):
<<<TASK
{upstream prompt, e.g. "# Exercise 4: Prepare |-> state ... def prepare_minus(qc, q): ... pass"}
TASK>>>

{"code": "<the complete Python module>", "p_correct": <number from 0 to 1>}

Candidate module (frozen): <<<CODE {frozen code} CODE>>>
Reply with exactly one JSON object and nothing else: {"p_correct": <number from 0 to 1>}

模型

Generator：Qwen3-235B（temperature 0，max_tokens 8192，JSON 模式）、gpt-oss-120b（medium reasoning，32768，JSON 模式）、 Sonnet 5.5（adaptive thinking，effort high，结构化输出）。Verifier 沿用 GPQA 的五个候选：gemini-3.7-flash、gemini-3.5-flash-lite、 mistral-small、mistral-medium、claude-haiku-4-5，设置与 GPQA 相同。每个候选的五个 verifier 信号都收集，策略只读取它决定查询的那部分。

Calibration 与 evaluation 的划分

同一 kata 里的题多是逐步加难的近似变体，若拆到两边会让评估结果被近似题抬高。因此我们以 kata 为单位分组 （tutorials、examples 按子目录），参考解 token Jaccard ≥ 0.8 的跨组近似题合并，得到 35 组； 用在生成前固定的种子 20261019 把组分为 5 折（65/65/64/64/64），同一题的候选永不跨折。 采用 5 折交叉拟合，是为了让每道题都恰好在样本外被评估一次，避免单次划分的偶然性：每一折轮流作为 evaluation， 其余 4 折作为 calibration。

Verifier likelihood 与决策规则

在 calibration 折上，对每个 verifier 把分数分成 3 个等宽档 x ∈ {[0, ⅓), [⅓, ⅔), [⅔, 1]}，用 Laplace 平滑估计通过与失败条件下各档的概率； 多个 verifier 在给定是否通过时视为条件独立。先验 b₀ 取 generator 的 raw r。每问一个 verifier 就用 Bayes 规则更新信念：

P(x | y) = (ny,x + 1) / (ny + 3), y ∈ {通过, 失败}
b′ = b·P(x|通过) / [ b·P(x|通过) + (1−b)·P(x|失败) ]
A(b) = max(0, (1+L)·b − L) （停止并接受或弃答的价值；接受当且仅当 b ≥ L/(1+L)）
Qk(b) = −λ·ck + Σx P(x|b)·Jk+1(b′), Jk(b) = max(A(b), Qk(b))

奖励 1、错误损失 L、弃答 0；ck 是该 verifier 在 calibration 折上的平均 token 费用，λ = 每美元 10 个效用单位。 只有在 Qk(b) 严格大于 A(b) 时才继续问下一个。三个 verifier 的顺序在每个 calibration 折上从 60 种有序组合中选， 标准是 calibration 先验下的平均 J₀，同时考虑区分能力和成本。主设定 L = 19（阈值 0.95），这些设置都与 GPQA 相同。

局限

区间来自留出样本的 bootstrap，不包含拟合和顺序选择的不确定性，也不是风险保证。28 道开发题曾用于调试 prompt。 使用同一官方 checker 是与他人结果对齐的必要条件，但题集和输出格式不同，不能说复现了别人的实验。费用为 usage 估算，全量约 $7.6。

附录 A

把 r 校准成先验之后

为什么做：决策规则把 b₀ 当作真实概率，接受阈值 L/(1+L) 只有在先验大致校准时才对应"错误率 ≤ 1/(1+L)"。 三个模型的 r 都系统性偏离实际通过率，这个附录检验：如果先验本身是校准的，顺序验证能否达到目标。 它是在看到正文结果后加入的次要分析，不改变正文结论。

怎么做：在每个 calibration 折上用单调分箱（GPQA 代码中的 fit_prior_calibration）拟合 r → 先验， 只用 calibration 折的标签，然后其余流程与正文完全相同。
